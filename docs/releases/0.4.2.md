## CatalyX 0.4.2

A fix for a boost that could get stuck: some Windows services can be stopped by anybody but started again by
nobody but Windows itself. CatalyX stopped such a service, could never put it back, and the leftover record
blocked every later restore.

### Fixed
- **A restore always finishes.** A service that Windows refuses to let anybody start again (`WdiSystemHost` and
  `WdiServiceHost`, the Defender diagnostic services, are the common ones) is no longer stopped at all, because
  a change that cannot be undone is not made. And if such a record is left over from an older version, it is
  dropped with a clear note instead of blocking the next restore for ever.
- **"needs administrator rights" was the wrong message.** That appeared even when CatalyX was already running as
  administrator. Windows error 5 while elevated means "Windows protects this service", not "you are not admin",
  and the log now says so.
- **Records of services that did not stop are taken back out** of the recovery journal, so a service that Windows
  refused to stop cannot leave a boost that "needs restoring".
- **The counts are honest.** "This boost will" and the Services page now count only the services that can really
  be stopped, and the Services page says "Cannot be started again" for the ones Windows protects.

### Download
`catalyx.exe` (the window), `catalyx-cli.exe` (the command line). Verify each against its `.sha256` file.
Windows 10/11.

If a previous version left a boost half-restored, run `catalyx restore` (or press **Restore now** in the window)
once with this version: it clears the leftover record and finishes the job.
